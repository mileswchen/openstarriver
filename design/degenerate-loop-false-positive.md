# 退化循环检测器误报：模板化枚举（论文卡）修复方案评审

状态：评审稿（待决策，未实施）
关联：WI-200（exact 通道）、WI-210/BUG-152（paraphrase 通道）、turn-12 宿主 wait 终态语义
触发案例：starpaper「20 篇论文卡」深度任务被 `DEGENERATE_LOOP` 中止，badge「完成 · 44 字」

## 1. 问题定性（已用复刻器证实）

`DegenerateLoopMonitor`（`crates/starriver-agent-loop/src/degenerate_loop.rs`）只被喂
`StreamChunk::TextDelta`（`agent.rs:1182-1184`），即**助手散文流**；工具调用参数与工具结果
**不进检测器**。

检测器双通道：
- exact（`exact_repetition_tripped`, :90）：取 `last_sentence(window)`，按长度定阈值
  （≥12 字重复 5 次 / 2..12 字重复 40 次），用 `window.matches(last).count()` 子串计数。
- paraphrase（`paraphrase_tripped`, :113）：≥6 字句、尾 ≤24 句、≥10 个近义副本
  （字符多重集 Dice≥0.75、每句≥2 表亲），且需≥1 句原样重复≥2 次「上膛」。

**误报机制**：句子分隔符含 `.`（`SENTENCE_TERMINATORS`）。论文卡的
`OA链接：https://arxiv.org/pdf/<id>` 与 `DOI：10.48550/arXiv.<id>` 被 `.` 切成
`OA链接：https://arxiv` / `org/pdf/<id>` 等**样板碎片**。这些碎片≥12 字、每卡一模一样，
第 5 张卡时 `window.matches("OA链接：https://arx")` 凑满 5 次 → exact 触发。
`last_sentence` 还会取**正在流式输出的半截前缀**，它能在前面每张卡的完整 OA 行里匹配子串，
于是模型还在正常吐第 5 卡就被掐断。

**复刻器实锤**（忠实复刻双通道 + 2000 字尾窗 + 7 字分块喂入）：
- 合法 20 卡（内容互异）：baseline 在 ~973 字符（≈第 5 卡）TRIPPED=True，通道=exact，
  触发句 `OA链接：https://arx`（16 字）×5。
- 对照：多样化编程输出（不同函数名/逻辑/标识符）→ exact=False。
- 旁证：失败任务的压缩摘要 gather 到 **19 篇互异论文**——真退化循环会卡在同一句无限重复，
  不会收集 19 个不同条目。故大概率是**误报**而非真循环（无原始流文本，不能 100% 排除真循环）。

**为什么编程任务不触发**：编程输出真正多样，无句子被原样回收，exact 凑不满重复次数，
paraphrase 的 Dice 远低于 0.75。文献卡是「重样板 + 轻变化」，天然踩中 exact 通道。

## 2. 方案 1：宿主检测器枚举感知（保护所有任务）

### 1a — URL/DOI 屏蔽（必要但不充分）
分句前用正则把 `https?://\S+` 与 `10\.\d{4,9}/\S+` 替换为占位符，避免内部 `.` 产生碎片。
- 复刻验证：**单独使用仍触发**（~1022 字符），残余触发句 `来源：arXiv API`（12 字）×5。
  即屏蔽 URL 只是把触发句换成下一个样板标签。
- 定位：防御性硬化，抬高枚举窗口多样性、减少碎片，但**不能单独解决问题**。

### 1b — 多样性闸门（⚠️ 见 §6 修正：仅对啰嗦格式有效，非通用解）
在 `tripped()` 入口加一道否决：统计窗口内**≥6 字的不同句子数**（HashSet，O(n)），
若 `distinct >= K`（建议 K=20）则判为「正在产出新内容」直接放行，不进入双通道。
原理：退化循环 = 重复且**无新内容**（窗口被回收内容占满，不同句极少）；
模板枚举 = 样板重复但**载荷互异**（标题/ID/概述各不相同，不同句很多）。
- 复刻验证（K=20，全部正确）：

  | 用例 | 窗口不同句数 | 期望 | K=20 结果 |
  |---|---|---|---|
  | 合法 20 卡 | 61 | 不触发 | 不触发 ✓ |
  | 同一卡重复×20（真循环） | 13 | 触发 | 触发 ✓ |
  | 双卡交替循环×15（真循环） | 19 | 触发 | 触发 ✓ |
  | paraphrase 循环 | 10 | 触发 | 触发 ✓ |
  | 写实现。×200 / ×40（短句循环） | 0 | 触发 | 触发 ✓ |
  | 长句×5 / ×4 | 1 | 触发/不触发 | ✓ |
  | ascii 循环×60 | 1 | 触发 | 触发 ✓ |
  | normal_prose / distinct_stepwise / small_family | 3/12/8 | 不触发 | 不触发 ✓ |

  12 个现有测试形状全部保住。K=16 会漏掉双卡交替循环（19≥16），K=20/24 通过。
- 为什么能解决：把判据从「单纯重复」升级为「重复且缺乏新内容」，正面区分循环与枚举。
  合法卡窗口 61 个不同句远超 K；真循环（含同卡/双卡重复）不同句 ≤19 低于 K。
- **局限（诚实）**：
  1. 多模板循环逃逸：若模型循环吐出 **≥3 张互异富模板卡**（不同句 ≥~28≥K），闸门放行 → 漏报。
     K=20 与双卡交替（19）之间仅 1 的裕量，阈值敏感。
  2. 检测延迟：循环夹在新内容中开始时，窗口初期不同句多 → 暂放行，待循环占满窗口、
     新内容滚出 2000 字尾窗后才触发（会晚一些，但不会永久漏）。
  3. 阈值是经验值，需用回归测试矩阵钉死，不能拍脑袋。
- 成本：O(n) 一次 HashSet，无新增 O(n²)；改动集中在 `tripped()` 入口 + 常量 + 测试。

### 1c — 新颖度比例闸门（证伪，不推荐）
按「窗口中只出现一次且无近义副本的句子字符占比 ≥F 则放行」。复刻验证**多处失败**：
- 合法卡窗口 novel_frac 仅 **0.03**（字符多重集 Dice 把不同 arXiv ID/标题判成近义）→ 仍误报。
- 短句循环（写实现。4 字 <6）被长度过滤排除 → novel_frac=1.0 → **漏报真循环**。
结论：字符级新颖度度量本身踩中 paraphrase 同款盲点，且长度过滤漏短句；不做大量重构不可用。**否决**。

### 方案 1 推荐组合
**1b（K≈20 多样性闸门）为核心 + 1a（URL/DOI 屏蔽）为防御纵深**。
可选再硬化 exact 通道：重复计数按「整行/整句」而非子串匹配，杜绝半截 URL 前缀跨卡误匹配。
新增回归测试：① 20 卡枚举不触发；② 同卡×20 触发；③ 双卡交替触发；④ 既有 12 测试不回退。

## 3. 方案 2：starpaper 结构化输出走工具通道（架构最干净）

**杠杆**：检测器只看 TextDelta；工具调用参数 + 工具结果**不进检测器**。
paper-search SKILL.md 已强制「bash + 写 /tmp」（auto 档沙箱内放行）。顺势延伸：

- 技能改为：用 bash/python heredoc 把 20 卡**组装进 `/tmp/paper_cards_<runId>.md`**
  （可逐篇 append，每篇一次 bash 调用）；最后一步 `cat` 该文件 → **卡片全文落在工具结果消息里**。
- 助手散文只保留**简短、多样**的推理/小结 + 检索词 + API URL + 文件路径。
- 卡片经工具结果投影进消息流（宿主已投影 tool 结果），**检测器完全看不到枚举** → 永不触发。
- UI：renderTranscript 已展示「工具步骤 + 助手文本」；增强为把最终卡片文件渲染成卡片视图
  （读工具结果文本即可，**无需新增宿主 API**）。extractAssistantText 仍取助手小结。

- 为什么能解决：把病态输入（模板化长枚举）从检测器监视的散文通道**整体移走**，
  检测器保持简单且已被验证；不是教检测器容忍病态输入，而是消除病态输入。
  符合 agent 设计哲学（工具承载动作/数据，散文承载推理）。
- **局限**：
  1. 逐技能合作：每个结构化输出技能都要采纳；**不保护其他仍流式吐模板散文的插件/任务**。
  2. 模型可能无视技能仍在散文里吐卡 → 需技能显式约束 + 方案 1 作兜底。
  3. UI 需把工具结果里的卡片渲染好（否则用户只看到 bash 步骤）；属插件侧改动。
  4. 逐篇 bash 会增加工具调用次数/回合长度（但每次散文短，反而更不易触发停滞/循环）。

## 4. 有没有更好的优化方案

**第一性原理**：检测器监视散文；批量结构化数据本应走工具，而非散文。
方案 2 是这一原则的落地（治本、消除病态输入）；方案 1b 是模型 inevitably 流式吐结构化散文时的
**安全网**（治标但宿主级、保护所有任务）。两者互补，不是二选一。

更进一步的硬化（按性价比排序）：
1. **exact 通道整句计数**（替代子串匹配）：直接杀死半截 URL 前缀跨卡误匹配，与 1b 叠加。
2. **进度/活性信号**（未来）：真循环 = 长时间「无工具调用 + 无新内容」。原始 8h 事故正是
   「从不发工具调用」。但枚举期间也无工具调用，故须与新颖度信号合用；较复杂，建议后置。
3. **诚实暴露中止原因**（turn-12 宿主修复）：wait 终态加 reason 字段、插件 surfacing 失败，
   让即便误报也可见、可恢复，而非静默「完成 · 44 字」。这是把「误报伤害」降到最低的关键配套。

**推荐落地顺序**：
- 立即（插件侧、低风险）：方案 2 改 paper-search + UI 渲染工具结果卡片 → starpaper 任务不再被误杀。
- 紧随（宿主侧、需测试矩阵）：方案 1b（K≈20）+ 1a + exact 整句计数 + 回归测试 → 保护所有任务。
- 配套（宿主侧）：turn-12 wait 终态 reason + 插件失败 surfacing → 误报/真循环都可见可恢复。

## 6. 通用性分析（turn-16 修正， supersede §2 的乐观结论）

### 6.1 这是通用缺陷，不是论文工作台专属
检测器对**「固定模板 × N 条」流式散文**这一整类输出都会误报。复刻器测 6 种格式（20 条互异内容）：

| 格式 | baseline 首个触发通道 | 触发位置（字符） |
|---|---|---|
| Markdown 表格 | **paraphrase** | 483（≈4 行） |
| BibTeX 条目 | **paraphrase** | 336（≈3 条） |
| 测试用例清单 | **paraphrase** | 455 |
| 时间线 | **paraphrase** | 455 |
| API 端点清单 | **paraphrase** | 399 |
| 翻译对照 | **paraphrase** | 595 |
| 论文卡（啰嗦） | exact | 917（≈5 卡） |

**两个通道都误报**：紧凑格式样板行互为近义副本（Dice≥0.75）+ 原样重复上膛 → paraphrase 在 ~3 条就触发；
只有啰嗦的论文卡撑到 exact。故「只修 exact 通道」不成立。

**其他插件实证（xhs-seeding，已查 SKILL/UI 原文）**：
- `xhs-compliance` 输出 = Markdown 表格 `| # | 位置 | 类别 | 风险等级 | 改写建议 |` → 同上表格式，高危。
- `xhs-title-hooks`「输出 5-10 个候选标题」编号列表 → 模板枚举。
- `xhs-topic-research`「事实卡：内容 + 来源链接 + 可用在哪段」→ 含 URL 的模板卡，同论文卡。
- `xhs-workflow` / UI `app.js:55`「一次性产出完整素材包：10 个候选标题、正文、封面文案、发布前自查表，
  不要分步确认，直接给终稿」→ 强制单段长模板散文流，**最高危**。
- 受影响范围还不止插件：普通聊天里「列 N 个 / 给清单 / 出表格 / 逐条对照」同样中招。

### 6.2 为什么没有「一行阈值」的通用检测器补丁（系统证伪）
复刻器逐一证伪 4 类候选通用闸门（全部含真循环对照 + 12 现有测试形状）：

| 候选闸门 | 证伪反例 |
|---|---|
| 多样性闸门 distinct≥K（§1b） | 紧凑格式每条仅 1–3 个不同句，exact/para 在第 3–5 条触发时窗口还没攒够 K → 来不及放行；K=20 只对啰嗦论文卡有效 |
| 4-gram 新颖率 ≥R 全局否决 | paraphrase 循环新颖率高达 0.615、长句×5 小窗口 0.209 → 全局闸门把这些真循环一并放行（漏报） |
| 句子重复占比 dup_frac≥D 否决 exact | 流式早期窗口小、样板占比高 → 枚举在第 3–4 条触发那一刻 dup 仍高（满窗虽低）→ 早期触发盲区 |
| 抬高 exact 阈值 N + dup domination | N≥8 漏掉长句×5（仅 5 次，破坏现有测试）；且紧凑格式 paraphrase 仍触发，与 N/D 无关 |

**根因**：检测器用字符/句子统计近似「语义新颖度」。模板枚举 = 样板回收 + 载荷新颖，
统计上难以一刀切；任何**窗口内容比例闸门**在流式早期（新颖内容尚未累积）都有盲区；
 paraphrase 的字符多重集 Dice 还把不同 ID/标题误判近义。**不存在格式无关、流式位置无关的简单统计判据。**
检测器侧治本需要真正的「进度/语义新颖度」信号 + 覆盖多格式的回归语料，而非一行阈值。

### 6.3 真正通用的方案：架构层把结构化数据移出被监视的散文流
**第一性原理**：循环监视器只喂 TextDelta（散文）。批量结构化数据本应走工具/制品通道，而非散文。
把这一点做成**宿主级通用原语**（不是逐技能 bash 补丁）：

- **通用结构化输出通道（artifact / 工具结果）**：宿主提供一等公民出口，所有插件 + 聊天可用；
  内容进工具结果 / 制品存储，UI 渲染，**不进循环监视器**。模板枚举这一病态输入类被整体消除，
  而不是教监视器容忍它。符合「工具承载数据/动作，散文承载推理」。
- **为什么通用**：宿主原语处处可用，零逐插件改造即保护所有任务；模型把批量数据写进 artifact，
  散文只留推理与小结 → 监视器看到的散文天然短而多样。
- **局限**：仍需模型选择用通道（约定 + affordance，非强制）；故须配监视器安全网兜底。

**配套（缺一不可）**：
1. **监视器硬化（尽力而为安全网，接受残余风险）**：URL/DOI/代码掩码 + exact 整行计数（杀半截前缀跨卡匹配）
   + 按多格式回归语料调闸门。不宣称通用治本，只压低误报率。
2. **诚实暴露中止原因（turn-12 wait reason + 插件 surfacing）**：即便残余误报，也可见、可恢复，
   而非静默「完成 · 44 字」。这是把误报伤害降到最低的关键，且与检测器精度无关、独立有价值。
3. **（后续演进）进度/活性信号**：真循环 = 长时间「无工具调用 + 无新信息」。把新颖度从字符统计升级为
   语义级（句向量新颖率 / n-gram 相对历史基线增量），仅在「持续无进度」时触发。复杂度较高，列为演进方向。

### 6.4 修正后的推荐落地顺序
1. **通用治本（宿主）**：结构化输出 artifact 通道 + 技能通用规范「批量结构化数据走工具/制品，散文只放推理与小结」。
2. **通用兜底（宿主）**：监视器硬化（掩码 + 整行 + 回归矩阵）+ 诚实中止 surfacing（turn-12）。
3. **立即低风险（插件侧）**：starpaper / xhs-seeding 把批量产出改为 bash 组装 → 工具结果展示（§3 推广到所有结构化技能）。

### 6.5 待决策点（补充）
- 是否新增宿主 artifact 通道，还是复用「工具结果 + 文件」约定（后者零新原语，前者更通用易用）。
- 监视器安全网的回归语料范围（至少覆盖 §6.1 六格式 + 真循环对照 + 12 现有测试）。
- 是否把「结构化输出走工具」写进 PLUGIN.md / 技能模板，作为插件生态通用规范。
- 语义级进度信号是否立项（需嵌入模型/基线，成本较高）。

## 7. 参考系统对照：DSH 与 Codex 怎么解决（turn-17，本地源码实证）

读了本地 `deepseek-harness`（DSH，TS）与 `codex/codex-rs`（Codex，Rust）源码。
**结论：两个参考系统都不监视散文重复。** Starriver 的散文检测器是三者中独有的，
而 DSH 的设计笔记**逐条点名拒绝**了 Starriver 正在用的几种做法。

### 7.1 三系统对照

| 维度 | Starriver（现状） | DSH | Codex |
|---|---|---|---|
| 散文重复检测 | **有**：exact 子串计数 + paraphrase 字符 Dice≥0.75，喂 TextDelta | **无** | **无** |
| 动作（工具调用）循环检测 | 无 | **有**：`repeat-tool-reminder`，键=(工具名, 规范化参数)，连续相同计数 | 无 |
| 触发后动作 | **硬中止** Aborted(DEGENERATE_LOOP) + 强制压缩 + 降级 | **advisory 提醒**注入下一轮上下文，从不 block/改写 | 不针对内容动作 |
| 相似度/模糊匹配 | paraphrase 用 Dice 相似度 | **明确拒绝**（见 7.2） | 无 |
| 资源兜底 | 压缩阈值 0.8 | timeout-policy（单调用超时） | **token 预算** `BudgetLimited` 中止 |
| 重复工具输出处理 | — | — | **HeadTailBuffer 截断**（留头尾丢中间），非中止 |
| 守卫位置 |  baked 进 agent.rs 主循环 | **可选叶子插件**（"plugins, not loop changes"） | 预算在循环，内容不判 |

### 7.2 DSH：动作身份 + advisory + 插件（`packages/guard/repeat-tool-reminder`）

**检测对象是动作，不是文字。** 问题定义（feature note 原文）：模型「re-issues the same tool
call with byte-identical arguments — re-running a failing grep, re-reading an unchanged file,
polling a command that already gave its answer」。键 = `(tool name, canonical arguments)`，
参数深排序键 + JSON.stringify 规范化（忽略属性顺序）；连续相同 +1，不同 tracked 调用重置为 1。
**模板枚举散文根本不在监视范围内 → 零误报。**

**advisory，从不 veto。** 阈值默认 `[3,5,8]`：第 3 次温和提醒「分析上次结果，换方法或换参数」，
第 5/8 次详细提醒（点名工具、连续次数、规范化参数预览≤500 字符）。提醒以
`source:{kind:'plugin',form:'notice'}` 注入下一轮上下文，**模型自己决定**继续/换路/收尾。
每 agent 独立链（WeakMap），用户插话重置链，被 deny 的调用也计数（猛敲被拒调用正是该断的循环）。

**DSH 明确拒绝的替代方案（feature note「Alternatives considered」原文，与 Starriver 直接相关）**：
- **模糊/近义检测**（normalized paths、similar-but-not-equal arguments）——拒绝：
  「exact match after canonicalization is cheap, deterministic, and explainable to the model;
  **similarity thresholds invite false positives** and need evidence before they earn complexity.」
  → Starriver 的 paraphrase/Dice 通道正是 DSH 拒绝的东西。
- **在 agent-loop 里加步数/重复预算**——拒绝：「**plugins, not loop changes**；a hard step budget
  is a blunter, orthogonal control」→ Starriver 把硬中止 baked 进主循环，正是被拒绝的形态。
- **最高阈值升级为 block**——拒绝：「a blocked call **punishes legitimate identical repeats**
  (polling a long-running terminal, re-checking a file the agent expects to change), and an
  advisory reminder keeps the model in control」→ Starriver 的硬中止+强制压缩就是会误伤合法重复的 blunt 版。
- 把提醒塞进 tool result（改写 content）——拒绝：会让日志里的 tool/result 撒谎；用独立 additionalContexts 通道。

**已知局限（DSH 自陈）**：仅精确匹配（近义变体漏检）；压缩不重置链；advisory 不 block；
合法幂等轮询过阈值仍会被提醒（靠 thresholds/exclude 泄压）；纯散文循环不在其守卫范围。

### 7.3 Codex：不判内容，靠预算 + 输出截断

 exhaustive grep 确认 Codex **无散文重复检测器、无 identical-tool-call 提醒**
（`guardian/` 是审批/安全审查器；`has_same_tool_calls` 是 Code Mode 压缩元数据完整性校验；
`character_ngram` 是技能选择匹配——均与循环检测无关）。其兜底是两条正交机制：
- **token 预算**：`rollout_budget.rs` / `agent/control/budget.rs` → `SessionBudgetExceeded`，
  `TurnAbortReason::BudgetLimited`。预算耗尽才中止——**判资源不判内容**，无误报。
- **重复工具输出截断**：`unified_exec/head_tail_buffer.rs` 的 `HeadTailBuffer`
  （`UNIFIED_EXEC_OUTPUT_MAX_BYTES`，留稳定头+尾、丢中间）。命令喷 10 万行重复输出 → 截断，非中止。
- 回合自然结束：模型发出无工具调用的最终消息即收尾，信任模型 + RL 训练不空转。

### 7.4 对 Starriver 的启示（最小通用修复，被两个参考系统验证）

1. **停止监视散文重复**——这是误报类的根。两个参考系统都拒绝这么做；DSH 明言相似度阈值招误报。
   移除/中和 `degenerate_loop.rs` 的散文 abort，模板枚举误报**直接消失**，无需逐技能补丁、无需新原语。
2. **若要保留循环守卫，改监视动作身份**（DSH 蓝图）：键=(工具名, 规范化参数)，连续相同计数，
   精确、确定、可向模型解释、对枚举零误报。这是现成可移植的设计。
3. **advisory 而非硬中止**：注入提醒让模型自决，而非 Aborted+强制压缩。DSH 拒绝 block 因它误伤合法重复；
   Starriver 的静默「完成·44 字」正是硬中止的伤害。
4. **守卫做成插件/叶子，不 baked 进主循环**（DSH「plugins, not loop changes」）。
5. **资源预算作正交兜底**（Codex token budget）：限制空转成本而不判内容，无误报。
6. **重复工具输出用截断**（Codex HeadTailBuffer），非中止。
7. **诚实暴露中止原因**（turn-12）：即便保留任何中止，也可见可恢复——与检测器精度无关、独立有价值。

> 与 §6 的关系：§6 的「结构化数据移出散文流（artifact 通道）」是**锦上添花**的清洁化/UI 优化；
> 参考系统证明**修复误报并不需要它**——最小通用修复就是「停止监视散文 + 可选 advisory 动作守卫 + 预算兜底」。
> artifact 通道可后续立项，不是修误报的前置条件。

### 7.5 诚实局限（必须 surfaced）

改用动作身份检测后，**纯散文循环**（模型不调工具、只重复文字，如 turn-9 的「正在编写实现…」×200）
**不再被内容守卫捕获**，只剩 token/turn 预算兜底。DSH 与 Codex 都接受这一取舍：
用「零误报 + 预算限成本」换「放弃纯散文内容守卫」。鉴于误报伤害（合法枚举任务静默死亡）
远大于相对罕见的纯散文空转，参考系统的选择有据。Starriver 须明确拍板是否接受此取舍；
若不接受，纯散文循环需另设**语义级进度信号**（§6.3 演进方向），而非回到字符统计老路。

### 7.6 修正后的落地顺序（参考系统校准版）

1. **最小通用治本**：中和散文重复 abort（移除或降为 advisory  notice，不中止）。误报类整体消失。
2. **可选安全网（DSH 蓝图移植）**：advisory identical-tool-call 提醒插件（精确规范化键、每 agent、
   用户插话重置、阈值 3/5/8、参数预览≤500）；做成叶子插件而非主循环改动。
3. **正交兜底**：token/turn 预算（Codex 式）限空转成本 + 重复工具输出 HeadTail 截断。
4. **诚实中止 surfacing**（turn-12）：任何中止都暴露原因，可恢复。
5. **（后续）artifact 通道 / 语义进度信号**：清洁化与纯散文循环治本，非修误报前置。
